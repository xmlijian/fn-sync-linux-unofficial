## 下载到本地：读取 EAGAIN 与进度反馈修复

- 现象：右键「飞牛同步：下载到本地」后，读取/复制/打开同一 ISO 报「资源暂时不可用」；系统关闭了桌面通知横幅（`org.gnome.desktop.notifications show-banners=false`）时没有任何进度反馈。
- 根因：`11383d9` 引入的大文件 Range 读取会抢占 `hydrate` 持有的按文件缓存锁，且只等 1 秒就返回 `EAGAIN`；`flush` 对干净文件也走 `upload_ino`，下载期间空等 30 秒。日志可见 `file read failed ... os error 11` 与 `upload lock wait timed out`。
- 修复：`read_placeholder` 不再抢占缓存锁（该路径只读远端，由 `dirty` 标记兜底）；`upload_ino` 在拿锁前先判断 `dirty`；Nautilus 状态列改为强引用 `file_info` 并按时剪枝；桌面通知不可见时，`fnsync-ctl`（仅 GUI 入口 `FNSYNC_GUI=1`）弹出 zenity 进度窗。
- 验证：94 项默认单测通过（11 项条件测试跳过）；新增两项回归（hydrate 期间读取不 EAGAIN、干净文件上传不等待锁）；三项真实 FUSE 测试串行通过。

## 0.2.3-8：编辑器原子保存失败（rename ENOENT）

- 现象：GNOME 文本编辑器保存 `cc-t.txt` 时报「重命名临时文件出错：没有那个文件或目录」。
- 根因：编辑器原子保存会先创建 `.goutputstream-*` 临时文件再 rename。旧实现把它当普通新文件上传，上传成功即删除 overlay 记录；远端列表默认忽略点文件，随后 rename 无法解析源路径，返回 ENOENT。
- 修复：编辑器临时文件和同步过滤规则命中的本地文件按 scratch 处理——内容只留本地、不标脏、不上传、保留 overlay 可见性；rename 成正式文件时迁移本地内容，按目标原远端戳标记为脏并上传（远端同时变化仍保留 Conflicted Copy）。新增启动及每 60s 清理，删除旧版本误传的 `.goutputstream-*` / `.~*` 等残留（本地缓存和 NAS 同时清理）。
- 验证：98 项默认测试通过；新增真实 FUSE 回归覆盖「临时文件 → 覆盖已有目标」和「临时文件 → 新建目标」；原有读写/删除/改名回归通过。
- 文件管理器状态列只显示状态（未下载/已下载/下载中/上传中/释放中/等待下载/本地修改/操作失败），不再显示百分比、大小、速度、剩余时间；进度细节只放在 `fnsync-ctl` 的进度窗与终端输出。状态刷新改为 1s，并只在“显示相关字段”变化时 invalidate，避免进度高频刷新导致文件管理器界面抖动。
